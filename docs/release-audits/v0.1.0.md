## External compatibility reports known at release time

None. Apart from the two sets above, no one has reported running this app.

## Compatibility tiers, and what moved

This is the first release, so every tier is new. Plays video, verified by watching it: webOS 6.5.3 (C1) and webOS 4.4.3 (B8). Starts, and nothing further is known: every firmware image webosbrew has from webOS 3.4.0 up, by `tools/fwcompat.py` (startup only). Does not start: webOS 2 and older (missing symbols).

## Known issues at release, with provenance

- **MPEG-2 video.** The C1's buffer-feed pipeline stalls the Load when declared `MPEG2`, gives an audio-only service when declared `MPEG`, and refuses video-only with error 601 (#12). The app reads the stream's codec and shows a read-out naming the Dispatcharr fix (an H.264 profile).
- **DTS audio on 2020+ sets.** The C1 refuses a DTS stream; the codec correction declares what the stream carries, so the failure is the television's, not a mislabel (M5).
- **A channel that did not start its picture once.** During #46's smoke test (2026-10-19, 00:20–00:33 CDT) the telemetry-free build presented in 5 of 6 launches; the one that did not was its first launch after its first deploy, and it primed and issued Play with no presentation callback following. Main presented in 5 of 5 launches in the same window. Cause not determined.
- **Memory growth.** RSS grew from 123.8 MB to 137 MB over 105 minutes of playback (about 7.5 MB an hour), flat after a stream froze; threads (36) and file descriptors (89) were steady. Not attributed (2026-10-15 soak).
- **The frozen stream.** In the same soak the stream froze at 1 h 46 min with no read error or end of file logged. The app now ends a live stream whose playhead stands still for 10 s and tunes it again (#15); why the server's stream stopped was not determined.

## Deliberately not done

- **No crash reporting or analytics.** Removed before release by owner decision (#46; `docs/telemetry-removed.md`). The audit's `telemetry endpoints` row grades the binary for none.
- **No playback on webOS 5 and later was watched.** Those sets use a different video-plane library (`docs/webos5-port.md`); the app's exported-window path was proven on 6.5.x, but nothing between 7 and 11 has been watched with this app.
- **No HDHomeRun-protocol discovery.** The owner's server answers neither SSDP nor HDHomeRun's UDP discovery, so Setup scans the local network for the Dispatcharr API instead.
