## External compatibility reports known at release time

None. Apart from the two sets named in v0.1.0's audit, no one has reported running this app.

## Compatibility tiers, and what moved

The C1 (webOS 6.5.3) stays verified, on this release. The B8 (webOS 4.4.3) was verified on v0.1.0 and has not run this release: it is the owner's second set and was not available. That matters more than usual, because webOS 4 places the corner picture through ACB (`AcbAPI_setDisplayWindow`, by a new `acb_place` that resolves the same library `acb_start` already uses, with no new import) rather than the exported window, and that path has never been run. The startup tier is unchanged in kind: every firmware image webosbrew has from webOS 3.4.0 up, by `tools/fwcompat.py` (startup only; #57 reported the `dlsym` count unchanged at 19).

## Known issues at release, with provenance

- **MPEG-2 video and DTS audio.** As in v0.1.0's audit; nothing in this release touches either.
- **Memory growth.** As in v0.1.0's audit (about 7.5 MB an hour over a 105-minute soak, 2026-10-15). Not re-measured and not attributed.
- **A channel that did not start its picture once.** Recorded in v0.1.0's audit (one launch in six, 2026-10-19). Not seen since in the owner's use; the cause was not determined, so it is not claimed fixed and is dropped from the note only for want of any recurrence.
- **A TV whose clock is wrong now fails TLS to an HTTPS server.** #53 removed key mode, which recognised a Plex server by a remembered key when the clock was wrong; it never applied to a Dispatcharr server, so no v0.1.0 user loses anything.

## Deliberately not done

- **Multiview.** Investigated for this release on the C1: a second buffer-feed pipeline coexists with the main one only when the main declares a 1080p maximum and the second asks for the `sub_video` sink. Whether the second pipeline shows a picture and what happens to audio were not proven, so it was moved to 0.3.0 by owner decision (2026-10-25). Nothing of it is in this build.
- **No webOS 4 run of the corner picture.** See the tiers above; the note asks webOS 4 and 5 owners for a report.
- **No crash reporting or analytics**, as in v0.1.0 (`docs/telemetry-removed.md`).

## Release configuration

| | |
|---|---|
| flavour | `com.magness.dispatcharrtv` (stable) — the id users install; `FLAVOR: stable` is pinned in the release workflow's build job |
| cargo features | `RELEASE=1`, which drops `devtools` and `devtriggers` |
| built by | GitHub Actions, from the tag, at a path identical on every runner |
| toolchain | webOS NDK as pinned by the workflow, Rust nightly pinned by date in the `RUST_NIGHTLY` repository variable |

Changes since v0.1.0: #53 (Plex server-identity machinery out of the transport; the bundled ISRG roots now back any HTTPS server; a portless URL defaults to 80/443) and #57 (the Guide's corner picture). Outbound hosts are unchanged: only the user's Dispatcharr server and the logo URLs its channels name. No new file is written, and no listener, FIFO or other inbound surface is added.
